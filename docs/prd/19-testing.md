| TST-035 | TST-030 的"调度可注入"在 Go 里不现实：broker 每条连接一个协程、另有写出池，要让协程交错可重放等于换掉整个运行时。本项目据此把确定性拆成两层——**操作序列确定**（同一种子生成同一串操作，可原样重放）与**时间确定**（时钟与定时器注入）；网络、磁盘与调度仍是真实的。声称时不得含糊：能重放的是场景，不是逐条指令的交错。 | v0.1 |

## 9. 注入时钟的边界（实现期补充）

契约 08 要求全程注入时钟，但 `internal/pki` 与真实 TLS 链路的集成暴露出一条
硬边界：**证书有效期这一层永远无法用假时钟测试**。`crypto/tls` 校验
`NotBefore`/`NotAfter` 时读的是墙上时钟，拿注入时钟签出的证书在握手阶段即
被判为过期。

这条边界决定了测试的分工，须在测试代码中显式写明，否则后人只会看到一处
"莫名其妙用了 `time.Now`" 的例外：

| ID | 需求 | 状态 |
| --- | --- | --- |
| TST-090 | 涉及真实 TLS 握手的测试，证书须按墙上时钟签发；broker 自身仍用注入时钟。两者的分界须在代码注释中说明理由。 | v0.1 |
| TST-091 | 证书**有效期**的行为由单元测试在注入时钟下验证（不经过 TLS 栈）；证书**吊销**的行为由集成测试在真实握手下验证（吊销状态在注册表中，走注入时钟）。 | v0.1 |
| TST-092 | 断言「服务端拒绝了握手」不得只看 `Dial` 是否报错：TLS 1.3 下客户端发完 Finished 即认为握手完成，服务端对客户端证书的校验结果之后才以 alert 送达。必须真正读一次，并区分「超时」与「被拒」。 | v0.1 |

### 覆盖率档位的理由（实现期记录）

`STRICT_PKGS`（95% 门槛）当前为 `internal/mqtt`、`internal/authz`、`internal/shadow`。
下列包刻意**不**进严格档，理由是其剩余未覆盖分支需故障注入才能触达，
为凑数字去造那种测试会让测试集变脏而不增加信心：

| 包 | 覆盖率 | 剩余缺口的性质 |
| --- | --- | --- |
| `internal/pki` | 90% | `rand.Read`、`aes.NewCipher` 等加密原语失败 |
| `internal/registry` | 93% | `json.Marshal` 失败；已被前置校验挡掉的分支 |
| `internal/store` | 87% | 引擎内部错误路径 |
| `cmd/openiotd` | 76% | 薄分发层，真实逻辑在 `internal/server`（TST-100） |

| ID | 需求 | 状态 |
| --- | --- | --- |
| TST-115 | 不得为提高覆盖率数字而构造无法真实发生的故障注入测试。门槛的作用是暴露未测的真实路径，而不是让数字好看。包的档位与例外须在本处记录理由。 | v0.1 |

| TST-116 | 禁止对带缩进的 JSON 响应做字符串匹配断言。`"allowed":true` 永远匹配不上 `"allowed": true`，而这类断言的失败信息完全指不出真因。须解析后判断。本轮连续犯了三次。 | v0.1 |
| TST-117 | 新增顶层配置段后须有测试断言它在 `Default()` 中不是零值。落到零值的段会让对应功能被静默跳过，而不会让任何测试失败——本轮的控制台就这样被关掉过。 | v0.1 |
